# Scoreboard

`ave scoreboard` is supposed to regenerate the README results table from run records. Today it prints one ticket-05 stub line and leaves the table as hand-typed `_tbd_` cells.

## Sub-features

- `scoreboard-cli` prints the stub line via `ave scoreboard`.
- `scoreboard-make` prints the same via `make scoreboard`.
- `scoreboard-no-write` does not modify `README.md`.

## How to get to it (user POV)

- Run `ave scoreboard`.
- Run `make scoreboard`.

## Driving it with control-ave

Preconditions:

- `control-ave doctor` succeeded.
- `README.md` contains the results table with `_tbd_` cells (or filled cells if a later ticket already writes them). Record a checksum or `git hash-object README.md` before the command.

- **CLI entry.** Run `.cursor/skills/verify-ave/control-ave capture scoreboard -- cli -- scoreboard`. Exit code `0`. Stdout is `scoreboard: would regenerate the results table from run records (ticket 05).`
- **Make entry.** Run `.cursor/skills/verify-ave/control-ave make -- scoreboard`. Same stdout and exit `0`.
- **No write.** Run `git status --porcelain -- README.md`. It is empty. The results table in `README.md` is byte-identical to the pre-command file.
- **Proof.** Keep `artifacts/scoreboard/stdout.txt` and the empty porcelain output. The command ran. The README was not generated.

## Gotchas

- The README says every cell is generated by `make scoreboard` and never hand-entered. That is a commitment, not current behavior. A proof that the table still says `_tbd_` after `make scoreboard` is a pass for today's stub and a fail once the renderer exists.
- Run records live under `results/example-run/` (committed) and `results/runs/` (gitignored live writes). Scoreboard does not read them. Do not look there for scoreboard output.
- Do not edit the table by hand to "match" a future renderer. The feature is the command's effect on `README.md`.
